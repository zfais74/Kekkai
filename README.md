# Welcome to Kekkai (結界)!

A sandbox for Java bytecode manipulation that allows your agents to run in a controlled environment.
Kekkai is designed to be lightweight, fast, and secure.
Spinning up Docker containers, Firecracker microVMs, or heavy polyglot runtimes for every tool call adds cold-start latency, memory overhead, and serialization friction. Kekkai eliminates that infrastructure by establishing a kekkai (protective barrier) directly at the bytecode level—giving AI agents fast, deterministic, read-only execution over host data without risking host integrity.

## Inspiration
The idea for Kekkai was inspired by realizing the java community lacks a safe sandbox for bytecode manipulation agents. Since the JVM is a trusted environment with a rich class library, I believed we could leverage it to build a safe sandbox.

Current guarantees:
- Compiles snippets in memory.
- Verifies generated bytecode constant pool against an allowlist.
- Blocks reflection/class access patterns like `Class.forName`.
- Passes an immutable snapshot of context data.
- Enforces timeout with virtual-thread interruption.

Known limitation:
- Non-cooperative CPU-bound infinite loops may not stop immediately.
- Future work: bytecode instrumentation for loop/instruction budgeting.

## Quickstart
You can use Kekkai in your Java project with Maven or Gradle.
Here is a quick example using the built-in `readOnly` builder:
```java
KekkaiSandbox sandbox = KekkaiSandbox.readOnly();

Object result = sandbox.run("""
        List<String> words = (List<String>) ctx.get("words");
        return words.stream()
                .filter(word -> word.length() > 4)
                .toList();
        """,
        Map.of("words", List.of("agent", "sandbox", "jvm")),
        Duration.ofSeconds(2)
);
```
```java
// define the context data
var context = Map.of(
"users", List.of("Alice", "Bob", "Charlie"),
"threshold", 5
);

//  configure kekkai
KekkaiSandbox sandbox = KekkaiSandbox.builder()
.allowPackages("java.lang", "java.util", "java.util.stream")
.timeout(Duration.ofMillis(250))
.build();

// execute the agent-generated code safely
String agentCode = """
return users.stream()
.filter(u -> u.length() >= threshold)
.toList();
""";

List<String> result = sandbox.run(agentCode, context, Duration.ofSeconds(2));
// -> ["Alice", "Charlie"]
``` 



## Why Kekkai?

* Sub-Millisecond Cold Starts: Compiles and executes snippets directly in memory using standard JVM APIs—no container orchestration or IPC serialization required.
* Strict Allowlist Security: Instead of trying to maintain an endless blocklist of dangerous APIs, Kekkai inspects the compiled .class constant pool and rejects anything not explicitly permitted.
* Zero-Copy Context Passing: Safely expose domain objects to the agent via immutable snapshots, letting agents query, filter, and transform complex data structures natively in Java.
* Virtual Thread Isolation: Built for modern Java (Java 21+), executing untrusted tasks on lightweight virtual threads with strict timeout enforcement.

## How it works
Kekkai is a bytecode instrumentation sandbox that provides the following guarantees:
1. In-Memory Compilation: Agent-generated source code is compiled dynamically in memory without touching the host filesystem.
2. Constant Pool Verification: Before classloading, Kekkai parses the bytecode's constant pool and verifies every referenced class, method, and field against a strict allowlist. Dangerous entry points (System, Runtime, ProcessBuilder, Unsafe, java.io, java.nio, java.net) are blocked before a single instruction runs.
3. Reflection & Classloader Lockdown: Blocks dynamic class discovery and escape vectors such as Class.forName, MethodHandles, and custom ClassLoader instantiation.
4. Immutable Context Injection: The host passes an immutable snapshot of state into the sandbox, ensuring read-only execution with zero side effects on host memory.
5. Bounded Execution: The sandboxed class runs inside a dedicated virtual thread with a configurable timeout budget.
